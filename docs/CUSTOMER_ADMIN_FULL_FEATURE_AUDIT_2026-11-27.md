# 고객·관리자 전체 기능 및 상호 연동 점검

작성: 2026-11-27 KST. FE 기준 커밋 51dcc54. 고객 App.tsx의 실제 라우트 전체, 해당 화면·공통 컴포넌트·services/context/data, 관리자 apps/admin/src 전체와 현재 보유한 BE 명세/Controller를 대조했다. 공개 API는 읽기 확인했다. 인증 계정의 모든 조합을 브라우저로 실행한 E2E 결과는 아니며, 실제 결제·환불·삭제·정지 데이터 변경은 하지 않았다.

## 후속 수정 (같은 날, 사용자 즉시 반영 요청)

아래는 감사 당시 기록이며 다음 항목은 이후 로컬 소스에서 수정했다. 아직 이 수정의 커밋·푸시는 하지 않았다.

- C25: ActivitySamples에서 공개 /preview GET을 조회하고 샘플 이미지/전체보기/빈 상태/실패 재시도를 구현. 유료 PDF 발급 API를 호출하지 않음.
- C26: 결제 화면에서 소장/7일권 선택. quote와 create에 동일한 rental_activity_ids 전송. 금액은 서버 quote/주문 응답을 기준으로 유지. 선택 변경 시 이전 견적은 사용 불가.
- C58: 탈퇴 안내→체크 동의→최종 확인→DELETE /users/me→성공 후 세션 정리. 저장하지 않는 탈퇴 사유 수집 및 가짜 0개 보유량 제거. 실제 계정 삭제 테스트는 하지 않음.
- C06~09: 부모 가이드 2개 본문과 유형별 놀이 예시를 정적 콘텐츠로 작성, 빈 이미지 대신 텍스트 표시. API/CMS가 생긴 것은 아님.
- C01/04/05: 실시간/인기 순위 오인 표시 수정, 인기 페이지의 고정 예시 후기 제거. 추천 검색어/활동지 소개로 표시.
- C13: 숫자↔수학, 역할↔역할 놀이, 그림/색칠↔미술 놀이, 음악↔노래하고 춤추기 등 이름 별칭을 필터에 반영.
- C11: 데이터가 없는 준비물/장소 추천 조건은 선택 불가 및 안내. 원본 데이터 계약은 여전히 필요.
- C35/36: 결제 수단은 실제 사용하는 카드 결제로 표시. 카드 관리/카드 등록 라우트의 미연결 입력폼 대신 준비 안내. 계좌/계약의 정적 예시 화면도 준비 안내로 대체.
- C37~40/51~64 일부: 프로필 지갑 0 고정 대신 준비 중 표시. 리뷰·활동·문의·알림·지갑, 도감·리포트의 미저장/미집계 상태를 명확히 안내. 문의는 확인된 고객센터 이메일 제공.
- C43: 날짜가 없는 주문의 기간 필터를 임의 구현하지 않고 미동작 선택 UI 제거, 전체 기간 조회로 명시.
- C62/67: 가짜 공지 2개/날짜/skeleton, 고정 버전0.0.0 및 최신 판정 제거.
- A11: 관리자 필터를 보유 BE 계약과 대조해 미지원 processing은 추가하지 않고, 잘못 사용하던 failed를 실제 payment_failed로 수정. 고객·관리자 상태 이름도 보완.
- 회귀 테스트 추가: 견적/주문 기간제 계약 일치, 고객 샘플 공개 조회, 탈퇴 DELETE/실패 전달, 카테고리 별칭. 전체 23개 통과. 고객/관리자 타입 검사 및 양쪽 Pages 빌드 통과.
- 로컬 브라우저에서 부모 가이드 본문, 상품의 샘플 빈 상태(실제 공개 API 결과), 카드 추가 준비 안내를 확인. 유료 주문 생성/실제 탈퇴는 실행하지 않음.

만세도감 지급·사진 검수·리뷰·성장 리포트 등의 서버 엔진은 이번에 새로 구현하지 않았다. 준비 안내 정비를 기능 연결 완료로 보지 말 것. 기존 API 연결 변경은 브라우저와 테스트로 확인하되 유료 실결제/탈퇴 같은 실제 데이터 변경 검증은 별도로 수행할 것.

## 1. 결론

- 회원/아이/상품/찜/장바구니/소장 주문/발급 PDF/관리자 매출·주문·환불의 기본 연결은 있다.
- **만세도감은 실제 활동으로 채울 수 없다.** 획득 결과가 항상 빈 배열이고 집계/지급 API가 없다.
- 부모 가이드는 고정 제목 2개에 상세 본문이 skeleton이다. 조회/편집/발행 경로가 없다.
- 실시간 검색어는 고정 단어이고 조회/검색 집계 API가 없다. 인기 TOP3도 구매·조회 순위가 아니다.
- 리뷰·활동 인증·성장 리포트·문의·공지·알림·지갑·카드·쿠폰·포인트는 화면 대비 실제 처리가 비어 있다.
- 관리자 미리보기 이미지는 연결했으나 **고객 상품 상세가 해당 API를 읽지 않는다**. 양쪽 연결이 끊긴 핵심 지점이다.
- BE에 있는 회원탈퇴와 7일권 주문 계약도 고객 화면에 연결되지 않았다.

## 2. 구분 기준

| 표시 | 의미 |
|---|---|
| 연결 | 실제 API 호출 코드 존재. 모든 운영 성공을 보장하지 않음 |
| FE 미연결 | BE 명세/코드에 계약이 있지만 해당 UI가 호출하지 않음 |
| 계약 필요 | 현재 확인한 BE 계약에 기능이 없음. 임의 API/필드를 만들면 안 됨 |

## 4. 만세도감: 실제 채우기 가능 여부

**현재 불가능.** `src/lib/badge-examples.ts`의 badgeExample은 아이·회원 행동과 관계없이 `{earned: [], representative: undefined}`를 반환한다. BadgeBookPage는 이를 그대로 사용해 earnedCount=0, 전부 잠금으로 표시한다. 회원가입/실제 구매/찜을 완료해도 배지를 지급하는 호출이나 재조회가 없다.

추가 문제:
- 대표 배지 저장은 localStorage뿐. 서버/다른 기기/관리자에 동기화 안 됨.
- 현재 대표 지정은 sparkles의 3종(만세왕/골고루 요정/명예가족)이며 획득한 경우에만 가능. 지금은 획득이 없어 실행 자체가 열리지 않음.
- 누구의 성과인지 단위 합의 필요: 회원 계정 vs 아이. 아이 전환을 지원하므로 소유·조건 기준을 서버에서 정의해야 함.
- 관리자에는 배지 마스터·조건 수정·수동 지급/회수·지급 이력 메뉴/호출 없음.
- 중복 지급 방지, 환불·리뷰 삭제·탈퇴 시 처리, 지급 시각, 대표 변경 계약 필요.
- 버튼을 강제로 열거나 FE에서 획득 true로 만드는 것은 실제 발급 구현이 아님.

| 고객 리뷰→관리자 리뷰→배지 | 작성 저장부터 없음 | 리뷰 계약+관리+배지 엔진 |
| 고객 사진 인증→관리자 검수→도감/리포트 | 모든 처리 경로 없음 | 인증/검수/집계 계약 |
| 가입/구매/찜→배지 지급 | 원본 API는 있으나 보상 연결 없음 | BE 이벤트·조건 엔진·조회 |
| 대표 배지→프로필/타기기 | 로컬 저장 설계만, 현재 획득 불가 | 대표 배지 서버 저장·프로필 반영 |
| 고객 문의→관리자 답변→고객 이력 | 양쪽 빈 UI | 문의 API 전체 |
| 관리자 공지→고객 공지/알림 | 양쪽 빈 UI | 공지/발송/알림 API |
| 관리자 쿠폰/포인트→고객 지갑→결제 할인 | 양쪽 미연결, 결제 wallet 미주입 | 원장/할인 계약+정산 검증 |
| 고객 탈퇴→계정정리/기록보존 | 서버 구현 있지만 FE 미호출 | 기존 API 연결·보존 안내 정합성 |
| 관리자 환불→고객 권한/매출 | 기본 API는 연결 | 실유료 테스트 검증 필요, 미구현으로 오인 금지 |
| 카테고리 등록→아이 관심사→맞춤 추천 | 실제 ID는 연결. 현재 데이터 등록 완료 | 이름/코드 표준화·저장 재조회 검증 |

## 12. 이번에 읽기로 확인한 배포 데이터

- GET /activity-categories: 16개. ID1 테스트, ID2~16은 글쓰기/미술 놀이/만들기/그림 그리기/노래하고 춤추기/대근육/소근육/책 읽기/가게 놀이/역할 놀이/한글/영어/수학/탐구/한자.
- 공개 활동지 count=1. activity ID1의 categories=[1](테스트), 난이도 easy, sale_status=on_sale.
- 해당 활동지 age_min_months=3, age_max_months=3. UI는 개월 필드이므로 만3세 상품 의도라면 36개월 등 실제 값 정비 필요. '3'을 입력하면 3세가 아님.
- GET /activities/1/preview: preview_urls=[]. 이 상품의 샘플이 비어 있는 것은 현재 서버 데이터도 없음. 업로드 후에도 고객 상세가 자동 표시하지 못하는 FE 단절은 별개.
- 실제 응답 필드: id/title/price/rental_price/rental_days/sale_status/description/age_min_months/age_max_months/difficulty/duration_min/duration_max/categories/image/pdf. 준비물/장소/발달영역/가이드/배지 없음.
- 공개 상품 count=1이므로 빈 카테고리 결과 전부를 버그로 판단할 수 없음. 카테고리가 테스트에만 붙어 있어 다른 이름 탭이 비는 것은 현재 상품 분류 데이터 문제도 있음.

## 13. 우선순위 제안

### P0: 보이는 기능과 실제 동작의 차이를 먼저 줄이기
1. 고객 구매 전 미리보기 GET 연결(실제 유료 PDF Viewer로 보내지 않기).
2. 소장/7일권 선택과 rental_activity_ids 연결.
3. 가입/구매해도 안 열리는 배지·작성 불가능한 리뷰·생성 불가능한 리포트 안내를 명확히 하거나 비노출 결정.
4. 인기 TOP3의 예시 리뷰/고정 검색어를 실제 통계처럼 표시하지 않도록 명칭·예시 표시 정비.
5. 고객 탈퇴 기존 DELETE API 연결 및 실제 안내 검증.
6. 상품 월령/카테고리 데이터 정비와 명칭 통일.

### P1: 핵심 사용자 활동 완성
- 리뷰/사진 인증 접수→관리자 처리→활동 기록→배지 지급→성장 집계의 API 계약을 함께 설계.
- 부모 가이드 본문/이미지 채우기 및 운영 등록 경로.
- 문의/공지/알림 실제 왕복 기능.
- 비공개 상품 관리자 목록/상세 및 normal DB/API 지원 확인.
- 유료 테스트 결제·환불·기간 만료·다운로드 권한·매출 연계 검증.

### P2: 확장 운영
- 지갑/쿠폰/포인트·등록 카드(현재 비어 있는 UI는 과도한 정보 입력을 받지 않게 정비).
