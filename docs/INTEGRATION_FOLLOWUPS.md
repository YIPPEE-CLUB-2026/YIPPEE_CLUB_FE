# 연동 확인 및 후속 작업

## 2026-11-26: PDF 다운로드 횟수 집계

- 현상: 사용자는 내려받기를 한 번 눌렀지만 관리자 발급 이력에 2회 표시.
- 확인한 FE 동작: ViewerPage 진입 시 발급 PDF를 fetch해 blob 미리보기를 생성하고, 내려받기 클릭 시 새 링크로 PDF를 다시 GET함.
- BE 명세: 발급 링크로 PDF가 제공될 때마다 다운로드 기록을 남김. 저장 버튼 클릭만 집계하는 방식이 아님.
- 원인: 정상적인 화면 진입과 저장이 각각 파일 전송으로 기록됨. 개발 모드 재실행이나 새로고침도 추가 요청을 만들 수 있음.
- 후속 FE 검토: 이미 받은 blob을 저장에 재사용해 중복 파일 전송 줄이기. 파일명·버전·권한 정책과 함께 검토.
- 후속 BE 협의: 열람/전송/저장 요청을 구분할지 결정. 사용자의 실제 디스크 저장 완료는 서버 전송만으로 보장할 수 없음.
- 기존 2회 기록은 임의 수정하지 않음. 이력·환불 판단 기준에 영향을 줄 수 있어 정책 합의 필요.
- 상태: 원인 확인 및 기록 완료. 동작 변경은 아직 적용하지 않음.

## 2026-11-26: 고객 주문 상세의 결제 정보

- 주문 조회는 GET /api/v1/orders 및 GET /api/v1/orders/{id}로 이미 구현·연결됨.
- 현재 명세의 고객 주문 상세에는 id/status/items/total_amount/refund_request만 있고 paid_at/created_at/payment_method가 없음.
- FE는 날짜를 '서버에서 제공하지 않음', 결제 수단을 '토스페이먼츠'로 고정 표시함.
- 0원 주문도 토스 결제처럼 표시되는 것은 부정확하므로 무료 주문 문구 구분 필요.
- BE 요청: 고객 본인 주문 상세에 주문 생성 시각, 결제 완료 시각, 실제 결제 수단 추가. 무료 주문의 처리 기준도 명시.
- 관리자 주문 상세는 별도 계약으로 paid_at 등 제공. 고객 앱에서 관리자 API로 보완하지 않음.
- 상태: 현황 기록. UI·응답 계약 개선 필요.
