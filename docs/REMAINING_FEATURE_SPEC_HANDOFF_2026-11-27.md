## 4. P0: 기존 연결과 운영 전제

### R01. 유료 결제·환불·기간제 구매 검증

**현재**: 토스 SDK/주문/승인/관리자 환불 API 연결. FE는 test_ck_만 허용. 라이브 전환 미완료.

**기존 계약**: POST /orders/quote, POST /orders, POST /payments/confirm, 고객 POST /orders/{id}/cancel, 관리자 reconcile/refund 및 refund-requests approve/reject, GET /purchases/activities, GET /admin/sales.

**수용 기준**:
- 테스트 클라이언트 키와 서버 테스트 시크릿 키가 같은 상점·세트. 키값을 문서/Git/프론트 시크릿으로 공개하지 않는다.
- 소장/기간제/혼합 선택에 따라 견적·주문 금액이 일치. 선택 변경 후 오래된 견적으로 결제 불가.
- 승인 성공 후 권한이 생기고, 실패·취소·새로고침·중복 callback에도 잘못 중복 지급되지 않는다.
- 0원 주문은 PG 없이 권한 부여되며 유료 테스트를 대체하지 않는다.
- 환불은 결제사 확인 뒤 완료되고, 고객 상태/기간제·소장 권한 회수/매출 환불 칸에 함께 반영된다.
- KST 일24칸·월날짜별·년12칸. 환불일 기준 집계 및 음수 순매출 확인. 0원 주문은 매출 제외.
- 실제 결제/탈퇴/환불 확인은 명시적으로 분리한 테스트 계정·상품으로 수행하고 운영 데이터 임의 조작 금지.

### R02. 난이도 normal API·DB

**현재**: FE 하=easy/중=normal/상=hard. 보유 BE 생성/수정/검색 검증 및 DB CHECK는 easy/hard.

**BE 작업**: 생성·수정·필터 enum normal 허용. 새 Flyway 마이그레이션으로 CHECK 확장(기존 V1 수정 금지). API_SPEC/Swagger 갱신. 배포본에 별도 반영됐는지 먼저 확인.

**수용 기준**: 중으로 등록→목록/상세→수정→고객 검색 가능, 기존 하/상 유지, 알 수 없는 값은 필드 오류. 상세: BE_DIFFICULTY_THREE_LEVELS.md.

### R03. 관리자 비공개 포함 상품 관리

**현재**: 목록은 공개 GET /activities. 비공개 상품은 ID 입력으로 일부 수정만 가능. 기존 필드/샘플 관리자 상세 조회가 없다.

**신규 계약**: 관리자 전체 목록·상세. 필터(공개상태/카테고리/검색어/페이지), 모든 저장 필드, 미리보기 목록 및 파일 메타를 합의한다. 정확한 API 경로는 BE 확정.

**수용 기준**: 비공개 생성 직후 전체 목록에서 발견→상세 기존 값 로드→편집→공개 전환→고객 노출. 미리보기는 비공개 고객에게 노출하지 않고 관리자만 확인. 공개 조회 404를 '이미지 없음'으로 오인하지 않는다.

### R04. 고객 주문 날짜·실제 결제 수단·기간 필터

**현재**: 고객 상세 응답에 날짜/결제 수단이 없어 날짜 미제공, 무료/토스 일반명. FE는 전체 기간만 안내한다.

**BE 확정 요청 필드**: 주문 생성 시각, 승인 시각, 실제 결제수단, 무료 처리 여부. ISO8601/타임존, pending/null 처리, 날짜 필터 기준(주문일 vs 결제일)을 명시한다. 관리자 응답을 고객 토큰으로 조회해 보완하지 않는다.

**FE 작업**: 확정한 필드로 날짜/수단 표시 및 1/3/6개월·1년·전체 필터. 금액·상품명은 주문 당시 값 유지. 삭제/비공개 상품 표지가 안 열리면 실제 상태 안내/대체 이미지.

**수용 기준**: 날짜 경계 KST, 무료/유료/미승인/환불 구분, 목록·상세 일치. 미래·알 수 없는 날짜를 임의 생성하지 않는다.

### R05. 사업자·정책 확정

**현재**: 상호/대표/사업자번호/주소/전화/메일/운영시간 입력. 통신판매업 신고번호는 확인 예정. 정책 4종은 초안/시행일 미정.

**운영·BE 확인**: 신고번호/해당 여부, 개인정보 보호책임자, 실제 수집항목/보유기간/탈퇴 처리, 수탁자·재수탁/국외 이전, 아동/법정대리인 동의, 소장 재다운로드·기관 라이선스, 디지털 공급/환불 조건. 토스 심사 피드백과 실제 결제 동의 문구 대조.

**수용 기준**: 실제 정보와 운영 동작이 일치하고 정책 버전/시행일 확정. 약관 동의 버전·시각을 서버에서 추적할 계약 확보. 이 문서는 법률 검토 완료를 선언하지 않는다.

## 5. P1: 활동·리뷰·검수·배지·성장 리포트

### R07. 리뷰 등록·조회·관리

**현재 고객**: /activities/{id}/reviews 및 /reviews/new는 폼/빈 목록/준비 안내. 저장·수정·삭제·도움돼요 API 없음. **관리자**: 리뷰 준비 탭만 있다.

**기능**:
- 고객: 구매/이용 조건을 통과한 회원이 별점·본문·사진 등록. 본인 삭제 정책, 사진만/최신/인기 필터, 도움돼요 추가·취소.
- 관리자: 목록/상세, 상품·회원·기간·상태 검색, 신고/숨김·복구 및 사유. 답변 기능을 운영할지는 확정.

**제안 데이터**: review_id, user_id, child_id(귀속 합의), activity_id, order_id, rating, content, photos, created_at, visibility, helpful_count, viewer_has_helped. 구매 검증·권한은 서버에서 수행.

**수용 기준**: 작성→새로고침→상품 상세/목록/관리자에 동일 기록. 타인 삭제 거절, 중복 제출 방지, 사진 업로드 실패 복구, 도움돼요 중복 방지. 리뷰 삭제·숨김이 배지 집계에 주는 영향 명시.

### R08. 활동 인증·사진·AI 검수·활동 기록

**현재**: 고객 사진 Blob 미리보기/아이 반응 선택만. 관리자 검수 표와 탭만. /records는 준비 안내.

**기능**:
- 고객: 아이·활동지·사진·반응·선택 메모로 접수, 접수 상태/반려 사유/재제출 확인.
- 서버: 로그인 계정과 issuance_code 소유 대조, 파일 유형·용량·개수, 중복/재제출 규칙, 사진 비공개 보관. AI 적용 시 판독 코드·작성 여부·신뢰도·중복 근거·실패 상태 저장.
- 관리자: 대기/AI 확인 필요/승인/반려 목록과 상세 원본, 코드·소유자·활동지 대조 결과. 승인·반려 사유/담당자/시각 보관.
- 고객 활동 기록: 승인된 항목의 날짜·아이·활동지·사진 및 상태 조회. 구매 PDF 다운로드와 활동 완료를 구분.

**제안 상태**: submitted → processing → needs_review → approved/rejected. 상태/동기·비동기/폴링 방식은 BE 계약 확정. AI 실패가 자동 승인으로 이어져서는 안 된다.

**수용 기준**: 등록 실패·해지·기본 변경·재로그인 정상, 계정별 격리, 결제 요청 수단과 UI 일치. 실제 카드 저장 계약 없이 폼만 다시 열지 않는다.

- 다운로드 지표를 '파일 GET/열람'과 '저장 버튼 요청'으로 나눌지 결정. 기존 4회 등을 임의 절반 보정 금지. 서버 전송만으로 디스크 저장 완료를 보장할 수 없음.
- 로그 전체 페이지 조회가 필요하면 최근100 이후 계약 추가.
- 수용 기준: 소유자 추적은 관리자만, 코드에 개인정보 노출 금지, PDF 생성 실패 시 원본 대체 제공 금지, 환불/만료 링크 거절.

### R22. 콘텐츠·라이선스·버전 운영

- 정답지/가이드 PDF·구독·페이지 수·상품 코드 등 확장 항목은 별도 상품 계약 필요.
- PDF.js 등 현재 배포 의존성/폰트의 라이선스 고지 검토. 일부 정적 목록만 있다고 전체 준수가 완료된 것은 아님.
- 웹 버전은 잘못된 0.0.0/최신 판정을 제거했다. 필요하면 실제 배포 버전/커밋/빌드 시각의 공개 메타를 연결한다.
- 수용 기준: 공개 버전은 실제 배포와 일치, 관리자/비밀 환경정보를 포함하지 않음.

## 8. 신규 API 공통 합의 항목

아래는 권장 계약 원칙이며 실제 경로/응답은 BE가 확정하고 API_SPEC에 반영한다.

1. 목록: page/page_size/count/results, 정렬·필터·검색 범위·최대값. 상세는 URL 직접 조회 가능.
2. 모든 ID와 null 의미, enum, 타임존/ISO8601, 파일 크기·개수·형식, 빈 상태를 명시.
3. 인증/관리자/본인 소유 검사. 민감 파일은 권한 있는 요청에서만.
4. 생성·승인·결제·지급에는 중복 요청 방지 키 또는 서버 유일 제약과 재시도 규칙.
5. 동시 처리·부분 성공·롤백·삭제/보존/감사 규칙. UI 성공은 서버 성공 이후에만.
6. 오류: 상태코드, 안정적인 code/message/details/request_id, 재시도 가능 여부를 명시. 실제 enum을 FE가 추정하지 않기.
7. 운영 상태가 공개/비공개/삭제/만료/환불일 때 고객·관리자 차이를 테스트.
8. 최종 명세와 예시 JSON, 변경 전후 호환성, 마이그레이션, 배포 커밋을 함께 전달.

## 9. 의존성과 작업 순서

1. 미커밋 FE 변경 인수·검토 → 기존 API 연결 검증(R01~06).
2. 상품 메타/분류(R11) 및 리뷰(R07), 사진 인증(R08) 계약.
3. 리뷰·인증·가입·구매 이벤트 → 배지(R09) → 성장 리포트(R10).
4. 가이드 CMS(R12), 실제 검색/인기 집계(R13).
5. 문의/공지/알림(R14~16), 준비 안내를 실제 왕복 기능으로 교체.
6. 지갑·카드·추가 계정·정산·발급 운영(R17~22)은 출시 범위에 맞춰 진행.

배지/리포트는 원본 이벤트·분류 없이 독립적으로 완성할 수 없다. 문의·공지·가이드는 관리자 발행/답변과 고객 조회를 같은 릴리스 단위로 묶어 검증한다.

## 11. 인계 시 반드시 할 일

- 현재 PC에서 `git status --short` 확인. 이 문서와 새 컴포넌트 등 untracked도 포함해 전달. diff만 복사하면 새 파일이 빠진다.
- 커밋·푸시 요청 전에는 자동 배포하지 않는다. 소스 전달본/별도 브랜치로 옮기면 환경파일은 안전하게 별도 설정.
- 노트북에서 최신 develop 체크아웃 후 전달 변경 적용·검사. 과거 main/feature/ui-layout 또는 유사 이름의 옛 폴더와 혼동하지 않기.
- 운영 테스트 계정/상품 식별, 실제 결제/탈퇴 실행 전 수행 범위와 복구 불가 여부 확인. 문서 작성/자동 테스트 중 실제 계정은 삭제하지 않았다.
- 실제 비밀번호/시크릿 키는 이 파일에 없다. NEXT_PUBLIC에는 공개 클라이언트 설정만.
- 각 R 항목은 'BE 명세 확정 / BE 배포 / 고객 구현 / 관리자 구현 / 자동 테스트 / 실제 E2E / 운영 검토'를 별도로 체크하고, 준비 문구만 바꾼 작업을 완료라고 기록하지 않기.
