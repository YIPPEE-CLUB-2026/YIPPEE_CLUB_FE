# 고객·관리자 미연동 및 부분 연동 재점검

기준일: 2026-11-28 (KST).

> **조사 후 FE 보완 반영**: P01/P02 찜 전체 페이지·별도 로딩/오류/재시도, P03 고객 활동찾기·검색의 서버 필터/정렬/20건 페이지 요청, P04 주문 목록의 요청 단위 이미지 캐시·카테고리 중복 제거·상세 동시 요청 최대 5건, P08 이름 선택 입력 통일, P09 추천 월령 KST 통일을 수정했습니다. 아래 표의 ‘확인한 현상’은 수정 전 조사 기록입니다. 구매 당시 썸네일 보존과 주문 목록 상품 요약 응답 확장 등 BE 협의 항목은 변경하지 않았습니다.
>
> 검증: 타입 검사·자동 테스트 31개 통과. 실제 검색 화면에서 결과 1건 → 나이 필터 적용 → 로딩 → 빈 결과 전환, 빈 결과에서도 필터 유지 확인. 전체 공개 자료 선조회는 홈/추천/저장 등 기존 용도에 남아 있으며, 활동찾기·검색 경로에서는 실행하지 않습니다. 추천 엔진 자체와 장소/준비물/발달 영역 API는 새로 만들지 않았습니다.

## 점검 범위와 판정

- 현재 FE 작업 트리, 최신 `BE_API_SPEC.md`, 실제 개발 서버 `https://api.yippeclub.com/v3/api-docs`의 메서드·경로를 대조했습니다.
- 서버에 데이터를 생성·수정하거나 결제·환불·탈퇴하지 않았습니다. 로그인 후 전체 사용자 흐름을 재검증한 보고서가 아닙니다.
- **API 없음**: 최신 명세와 공개 Swagger에 해당 계약이 없음. 문서에 누락된 별도 구현까지 없다고 단정하지 않음.
- **부분 연결**: 조회·입력 일부는 작동하나 서버 저장/전체 페이지/운영 설정 등이 미완성.
- **검증 대기**: 코드와 계약 테스트는 있으나 실제 계정·결제·파일 확인이 남음.
- 마지막 확인된 FE 커밋과 로컬 origin/develop은 `3eb0b3c`. PC 레이아웃과 최신 API 연결 등 후속 변경은 미푸시 상태입니다. 로컬 구현과 운영 배포를 구분해야 합니다.

## 1. 우선 처리할 부분 연결

| ID | 항목 | 확인한 현상·영향 | 필요한 작업 | 담당 |
|---|---|---|---|---|
| P01 | 찜 전체 페이지 | App.tsx에서 `/favorites?page_size=100` 한 번만 조회. 100건 초과 시 누락될 수 있음 | count/페이지 기준 전체 조회 또는 서버 페이지 UI | FE |
| P02 | 찜 로딩 상태 | savedIds를 먼저 비운 뒤 조회하며 별도 로딩 상태가 없음. 활동지 로딩이 먼저 끝나면 저장 목록에 ‘없음’이 잠깐 표시될 수 있음 | 찜 전용 로딩·오류 분리, 사용자별 상태 관리 | FE |
| P03 | 서버 검색·정렬 | 활동지를 전부 읽고 화면에서 검색·필터·정렬·페이지 처리. 서버가 제공하는 q/category/age_years/duration/difficulty/가격/sort/page를 화면 조건에 맞춰 사용하지 않음 | 검색/목록을 서버 쿼리로 전환, 요청 취소·빈 결과·페이지 경계 처리 | FE |
| P04 | 주문 목록 조회 비용 | 목록 → 주문마다 상세 → 상품마다 상세/카테고리 조회. 주문 수가 늘면 요청 수와 대기 시간이 증가 | 목록 응답 필드 우선 활용, 필요한 상세만 조회, 상품/카테고리 공유 조회. 목록 상품 요약은 BE 확장 협의 | FE·BE |
| P05 | 비공개·삭제 상품 주문 썸네일 | 주문 상품의 현재 공개 상세에서 이미지를 보완. 공개 상세가 404면 썸네일은 없어짐 | 주문 당시 표지 스냅샷 또는 구매자용 이미지 계약, 대체 표시 | FE·BE |
| P06 | 운영 결제 키 | paymentClientKey가 `test_ck_`만 허용. live_ck_ 등 다른 키는 오류 | 토스 계약 제품·운영 키 유형 확인 후 환경 구분. FE 클라이언트 키와 BE 시크릿 키 짝, 승인·환불 설정 확인 | FE·BE·운영 |
| P07 | 결제 복귀·중단 후 재개 | 콜백이 sessionStorage의 pending-payment에 의존. 저장 정보 없는 새 탭·다른 기기·유실 상황에 복구 흐름 없음 | pending 주문 재개 정책과 서버 대조/재확인 흐름 설계. 단순히 검증을 제거하면 안 됨 | FE·BE |
| P08 | 부모 정보 필수 조건 | 가입 화면 이름은 선택으로 바꿨으나 프로필 편집은 name.trim()을 필수로 검사. API에서 이름은 선택 | 이름 필수 여부 통일, 서버 profile_completed와 화면 검증 일치 | FE·기획 |
| P09 | 추천 시간대 | recommendActivities는 브라우저 로컬 날짜로 월령 계산. 다른 날짜 유틸은 KST | 해외 시간대·자정 경계에서도 KST 기준으로 통일 | FE |
| P10 | 무료 PDF 코드 정책 | 명세 6.4에 무료 공개 PDF는 토큰 없이 코드 없는 원본 다운로드 허용. 회원 코드 발급 경로도 별도 존재 | 무료도 반드시 발급 코드를 인쇄할지 결정. 필요하면 직접 원본 경로 정책 변경 | BE·기획 |

P03은 검색 자체가 작동하지 않는다는 의미가 아닙니다. 현재는 클라이언트 필터로 동작하며, 데이터 증가에 따른 요청량·응답시간 검증과 서버 검색 전환이 남아 있습니다.

| 관리자 비공개 상품 | 코드·경로·인증 바이너리 테스트, Swagger 경로 확인 | 관리자 로그인 후 목록/상세/표지/PDF/샘플 열기, 변경·공개 전환 |
| 중 난이도 | FE 선택지와 응답 매핑, 실제 normal 목록 필터 200 | 테스트 상품 normal 생성·수정·고객 검색, DB 저장 확인 |
| 토스 결제 | 요청 계약과 빌드 검사 | 테스트 결제창→승인→구매 권한→영수증→취소/환불, 운영 키/심사 별도 |
| 이용권 | 견적·주문 rental_activity_ids 일치 테스트 | 만료 전후 다운로드 차단·재구매·환불 권한 회수 |
| 다운로드 횟수 | Blob 재사용 회귀 테스트, 조회 API 연결 | 클릭 1회와 실제 GET 횟수·BE 로그·관리자 count 대조, 과거 2배 기록 원인 확정 |
| PDF 코드 | 발급 응답·코드 파일명 사용 | 실제 파일 왼쪽 아래 위치·모든 페이지·원본 도안 겹침, 무료 코드 정책 |
| 관리자 입구 보호 | 관리자 로그인·BE 권한 검사 있음 | Cloudflare Access 적용 여부, pages.dev 우회 포함 인증 전 차단. URL을 안다는 이유만으로 바로 화면을 열지 못하게 하는 요구와 구분 |

| 정책 고지 | 링크·내용·사업자 정보 있음 | 통신판매업 신고번호 확정, 실제 운영과 일치하는 정책 최종 검토 |

## 5. 이미 추가 연결했으므로 ‘API 없음’ 목록에서 제외할 것

- 부모 관계·연령대·profile_completed.
- 주문 created_at/paid_at/refunded_at/payment_method 및 since.
- 관리자 비공개 포함 학습지 목록·상세·인증 파일.
- 난이도 normal.
- 공개 샘플 이미지, 소장/7일권 주문 옵션, 회원 탈퇴.
- 관리자 일·월·연 매출과 발급 코드·다운로드 이력 조회.

단, 운영 사이트에 반영됐다는 뜻은 아닙니다. 미푸시 코드와 로그인 후 검증 대기를 따로 확인해야 합니다.

## 6. 권장 작업 순서

1. **FE 자체 보완**: 찜 페이지/로딩, 선택 이름 조건 일치, 추천 KST, 검색·목록 요청 구조.
2. **운영 전 확인**: 실제 결제/환불·PDF 권한/횟수·비공개 파일, 운영 키와 관리자 입구 보호.
3. **콘텐츠 입력 계약**: 카테고리 편집/삭제, 장소·준비물·발달 영역·활동 가이드. 관리자와 고객을 한 기능 단위로 연결.
4. **활동 핵심 흐름**: 고객 사진 인증/리뷰 → 관리자 검수 → 활동 기록/배지 → 성장 집계.
5. **운영 콘텐츠**: 문의·공지·프로모션·가이드 CMS·알림.
6. **부가 기능**: 쿠폰·포인트·캐시·저장 카드, 데이터 원장/환불 규칙 먼저 합의.
